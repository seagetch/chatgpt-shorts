# Shorts Reader Maintainer

## Overview

This skill captures the repo-specific rules for the shared short-story reader. Use it when changing reader behavior, regenerating pages, or checking how `doc.md`, `title.png`, and `title.jpg` are wired into the published site.

## When To Use

Use this skill when the task involves any of these files or behaviors:

- `book.html`
- `generate_reader.py`
- root `index.html`
- any work folder `index.html`
- pagination, spread layout, swipe or key navigation, font loading, social card metadata
- regenerating per-work pages after changing generator logic

## Workflow

1. Read [references/repo-layout.md](references/repo-layout.md) for the repo map and source-of-truth files.
2. If the change touches the shared reader runtime, edit `book.html`.
3. If the change touches generated wrappers or the root catalog, edit `generate_reader.py`.
4. Before generating any work folder `index.html`, confirm the story folder has `title.png` or `title.jpg`.
   - If neither exists, create a cover image that matches the story's content and save it as `title.png`.
5. After changing `generate_reader.py`, run:
   - `python -m py_compile generate_reader.py`
   - `python generate_reader.py`
6. Verify the reader over HTTP, not `file://`.
   - Local check: `python -m http.server`
   - Then open `/book.html?book=<folder-name>`

## Repo Rules

- `doc.md` is the source of truth for each story.
- Before generating `index.html`, each story folder should have a cover source: `title.png` preferred, `title.jpg` acceptable if already present.
- If no cover file exists yet, create a story-appropriate cover image and save it as `title.png` before running the generator.
- `book.html` loads `doc.md` and `title.jpg` at runtime via HTTP using the `book` query parameter.
- Each work folder `index.html` is a generated thin redirect to `../book.html?book=<folder>`.
- Root `index.html` is generated by `generate_reader.py`.
- `title.jpg` is generated from `title.png` by `generate_reader.py`.
- Do not rely on `file://` for reader behavior; runtime markdown loading is HTTP-only by design.
- Do not commit or push unless the user explicitly asks.

## Notes

- If pagination or layout breaks only after generator changes, regenerate all pages before judging the result.
- If runtime loading fails, check the folder name passed in `?book=` and confirm `doc.md` and `title.jpg` exist in that folder.

## Mandatory cover origin: image generation only

**Non-negotiable user requirement:** All new, replacement, or revised story cover artwork MUST originate from an image-generation model/tool. NEVER design or draw cover artwork with SVG, CSS, HTML canvas, vector shapes, procedural rendering, programmatic illustration, stock images, or manually assembled graphics. Programmatic operations are permitted ONLY to prepare an already image-generated picture for publication (crop, resize, JPEG encoding, noncreative metadata/hash checks). Do not replace already generated individual covers with a newly invented collage or synthetic vector artwork. If an image-generated cover already exists for the story, locate and reuse that exact artwork before considering new generation.

Public covers must be `title.jpg` (JPEG). Do not publish SVG covers, add SVG support to the reader for covers, or alter the established reader/generator contract to accommodate another artwork medium. If the generated source is PNG, encode that image to JPEG, without inventing new visuals. If user asks for an edit, preserve all unrequested image properties.

Before approval, verify image-generation provenance per cover: source identifier/path or generator result, the final JPEG's source relation, visual match to the story, correct folder, and published `title.jpg` reference. If origin is not established, mark FAIL and do not substitute a program-drawn image.

## Cover direction and visual review

- Read the story and its literary tone before choosing a cover. Choose composition, people or action, viewpoint, medium and palette to convey this particular work; changing only props is not enough.
- Avoid fixed genre templates. A quiet still life may fit one story, but "spoiler-free" does not require removing people, relationships or movement from every cover.
- Before accepting a cover, view the actual image beside the five most recent covers, not just their prompts. Check repeated composition, dominant colors, lighting, motifs and visual mood. If the new cover repeats the same visual formula without a story-specific reason, revise it.
- Check thumbnail readability, exact title text when present, consistency with the story, and absence of ending or solution spoilers. Record the chosen direction and actual visual comparison in the work's production notes.

## Genre-first cover design (mandatory for all new/replaced covers)

The cover must communicate the **actual genre and reader promise** at thumbnail size as well as the distinctive plot. Record the primary genre, target readership, cover concept, and reason for the chosen visual grammar in the work's `idea.md` or cover notes **before** image generation. The cover is not an abstract generic illustration merely decorated with one relevant prop.

- **小噺／落語的喜劇／短い笑い話**: readable comic situation, expressive gesture, active character interplay or visual incongruity, buoyant rhythm; if apt, theatrical or witty composition. Do not impose ominous cinematic stillness or solemn literary abstraction on a joke.
- **ライトノベル／キャラクター小説**: prioritize appealing, identifiable main characters, expressive faces, distinctive costume and relationship, clear genre premise and energetic anime/light-novel visual language; use the specific subgenre's visual grammar rather than a uniform cover template.
- **異世界転生（独立ジャンル）**: prioritize the protagonist's **newly reborn identity, body/species, age, social position, clothing, relationships and the distinctive reincarnated world**. If meaningful and spoiler-safe, hint at the contrast with the prior life through a clearly subordinate visual motif, not a confusing double-body composite. Convey whether the story is reincarnation comedy, adventure, slice-of-life, romance, power fantasy, or tragedy through characters' expressions, pose and scene. A generic magical castle or anonymous fantasy landscape alone is insufficient. Never depict a pre-reincarnation character design as the new body, invent a reincarnation mechanism absent from the prose, or make an unknown late reveal explicit.
- **異世界転移・召喚（転生とは区別）**: emphasize the protagonist arriving in a different world while retaining their original identity/body where that is the premise; show the actual encounter with unfamiliar society, geography, architecture or magic. Do not advertise this as reincarnation if no rebirth occurs.
- **悪役令嬢**: communicate aristocratic/fantasy court milieu, the heroine's agency, expressive attitude, costume, and relevant confrontation/romantic/comic tension; choose composition based on whether the work is comedy, reversal, drama, revenge or romance. Do not automatically use generic villainess stock iconography.
- **Mystery / horror / SF / adventure / romance / sport / literary**: select a correspondingly recognizable narrative image, with the scene, action, characters, atmosphere and visual conventions fitting that actual work. For adventure and sports, prefer legible action or competition rather than detached symbols unless the text warrants otherwise.

Before acceptance, assess the cover on **two separate gates**: (1) faithful to scenes, characters, setting, tone, with no invented devices or spoilers; (2) recognizable genre, subgenre, and intended readership without reading the blurb. A failure on either gate means revise the design. Realistic, pastel, sepia, minimalist, cinematic, anime, manga, illustrated-book, and graphic styles are **choices**, not defaults. Never override the genre's visual language because recent covers used a different style.

For recurring series, maintain character identity/recognizable design, but vary pose, action, framing and visual rhythm as demanded by each episode's genre. Review the actual most recent five cover images to avoid repetition. Do not conceal genre-specific character or action imagery under generic spoiler avoidance. Do not reveal the twist, culprit, solution or final scene merely to signal genre.

The final publication checklist must record the genre legibility gate and content fidelity gate as PASS / FAIL / NOT TESTED. The work is not cover-ready if either is FAIL or NOT TESTED. If image-generation or asset-upload capabilities are unavailable, do not quietly reuse a mismatched prior image or claim publication complete.
